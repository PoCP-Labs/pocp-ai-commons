# PoCP Open Core Strategy

## 1. Purpose

PoCP is designed as protocol infrastructure for verified contribution networks in the age of AI.

To become trusted infrastructure, PoCP must be open enough for communities, developers, agents, skills, tools, datasets, workflows, compute nodes, and organizations to inspect, implement, extend, and contribute.

At the same time, PoCP also needs long-term commercial sustainability, especially for advanced anti-abuse intelligence, neural routing, compute scheduling, enterprise governance, private deployment, and commercial API operations.

Therefore, PoCP follows an **Open Core** model.

## 2. Definition

Open Core means:

```text
Open:
protocol specifications
reference implementation
basic platform
SDKs
community tools
schemas
basic ledger
basic reputation
basic routing
basic anti-abuse rules

Commercial / restricted:
advanced anti-abuse intelligence
commercial neural routing
enterprise governance console
managed compute scheduling
private deployment tooling
commercial API gateway
advanced reputation / risk models
commercial support and managed services
```

## 3. Why PoCP Must Be Open

PoCP aims to answer:

> Who contributed what, who verified it, and how should rights be returned?

This requires trust.

Trust requires transparency.

The following must be open:

- contribution event schema;
- entity schema;
- capability schema;
- invocation schema;
- settlement schema;
- reputation schema;
- token measurement principles;
- human review principles;
- governance principles;
- reference implementation;
- SDKs and integration tools.

## 4. Why PoCP Cannot Be Fully Open

PoCP also needs to defend against abuse.

If all advanced risk logic is public, attackers may learn how to:

- farm CP;
- farm AI Credits;
- fake compute usage;
- manipulate reputation;
- collude in reviews;
- replay contribution events;
- exploit settlement rules;
- abuse sponsor pools.

Therefore, advanced anti-abuse logic, risk model weights, commercial neural routing, enterprise compute scheduling, and sensitive operational tooling may remain restricted or commercial.

## 5. Open Source Scope

### Always Open

- protocol specifications;
- schema definitions;
- reference implementation;
- basic AI Commons platform;
- basic CP / AI Credits / Compute Credits accounting;
- basic entity / contribution / wallet / ledger / reputation models;
- SDKs;
- CLI;
- MCP server;
- examples;
- documentation;
- contribution guidelines.

### Open Basic, Commercial Advanced

- reputation engine;
- neural routing;
- anti-abuse;
- compute adapter;
- settlement engine;
- governance assistant.

### Commercial / Restricted

- enterprise governance console;
- commercial API gateway;
- advanced anti-abuse intelligence;
- commercial neural routing optimizer;
- managed compute scheduler;
- private deployment tooling;
- advanced reputation and risk models;
- enterprise analytics;
- compliance audit console.

## 6. Principle

PoCP should be open where trust matters.

PoCP should be commercial where sustainability and security matter.

PoCP begins with contribution.
