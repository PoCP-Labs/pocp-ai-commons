# Code Contribution Commons

## Code contribution is not limited to writing code

PoCP AI Commons is an open-source project, but its code production process should not belong only to traditional programmers.

In the age of AI, code is produced through a chain of contributions:

```text
Idea / Need
→ Issue
→ Spec / Acceptance Criteria
→ AI-assisted Coding / Human Coding
→ Test
→ Review
→ Merge
→ Ledger
→ CP / AI Credits / Reputation
```

A meaningful code contribution may come from many kinds of participants:

- a user who describes a real problem;
- a product thinker who clarifies a workflow;
- an issue writer who turns a need into an actionable task;
- a prompt/spec contributor who writes precise Cursor or Agent instructions;
- an AI Agent that generates code or tests;
- a Skill that provides reusable coding capability;
- a human developer who implements and debugs;
- a tester who verifies behavior;
- a reviewer who protects quality, safety, and alignment;
- a document contributor who makes the system understandable.

PoCP should recognize the full code contribution chain.

## Why this matters

Traditional open-source contribution often focuses on merged code.

But in an AI-assisted development environment, many important contributions happen before and after coding:

- defining the right problem;
- writing a clear issue;
- creating acceptance criteria;
- designing API behavior;
- preparing a good prompt for an AI coding agent;
- reviewing AI-generated code;
- testing the actual workflow;
- documenting how to run and use the feature.

PoCP AI Commons should use itself to remember these contributions.

## Definition

A **Code Contribution Participant** is any human or intelligent entity that helps transform an idea into reliable, tested, documented, and merged code.

A participant may be:

| Participant | Possible Contribution |
|---|---|
| Requirement Contributor | Real need, bug scenario, user feedback |
| Issue Writer | GitHub issue, reproduction steps, acceptance criteria |
| Prompt / Spec Contributor | Cursor prompt, API spec, data model, test scenario |
| AI Agent | Code generation, test generation, refactoring, documentation |
| Skill | Reusable coding, testing, review, or documentation capability |
| Human Developer | Implementation, debugging, architecture, integration |
| Test Contributor | Manual test, automated test, bug reproduction |
| Documentation Contributor | README, setup guide, API docs, diagrams |
| Reviewer | Code review, security review, alignment review |
| Maintainer | Merge decision, release, governance, quality control |

## Code Contribution Pipeline

Every meaningful code contribution should ideally follow this pipeline:

```text
Need
→ Issue
→ Spec
→ Implementation
→ Test
→ Review
→ Merge
→ Contribution Record
```

### 1. Need

A participant identifies a real problem or missing capability.

Example:

> AI Chat should show the number of AI Credits consumed and the remaining balance after every message.

### 2. Issue

The need is converted into a GitHub issue with:

- problem statement;
- expected behavior;
- acceptance criteria;
- affected files if known;
- test scenario;
- priority.

### 3. Spec

A participant writes a precise development specification.

This may include:

- API shape;
- request/response examples;
- database changes;
- UI behavior;
- edge cases;
- Cursor prompt;
- test cases.

### 4. Implementation

Code may be written by:

- a human developer;
- Cursor;
- an AI Agent;
- a pair of human + Agent;
- a Skill-assisted coding workflow.

### 5. Test

The contribution is tested through:

- smoke tests;
- unit tests;
- manual workflow checks;
- screenshots;
- API calls;
- error case verification.

### 6. Review

A human reviewer checks:

- correctness;
- safety;
- maintainability;
- project alignment;
- AI-generated code quality;
- whether tests are adequate;
- whether documentation is updated.

### 7. Merge

Maintainers merge the PR if it meets quality standards.

### 8. Contribution Record

The contribution can later be recorded as a PoCP Contribution Event.

## Contribution Categories and Suggested CP

This is a non-binding draft. It is not a token allocation table.

| Contribution Type | Example | Suggested CP |
|---|---|---:|
| Need Contribution | Clear feature need or bug scenario | 5–15 |
| Issue Contribution | Complete issue with acceptance criteria | 10–25 |
| Spec Contribution | API spec, data structure, Cursor prompt | 20–40 |
| Code Contribution | Merged PR | 30–100 |
| Test Contribution | Smoke/unit/manual tests | 15–50 |
| Bug Contribution | Reproducible bug report | 10–40 |
| Documentation Contribution | Setup, API docs, diagrams | 10–50 |
| Review Contribution | Effective code or design review | 10–40 |
| Skill Contribution | Reusable Skill for coding/testing/docs | 20–80 |
| Agent Contribution | Agent-assisted code accepted after review | Agent reputation + human operator CP |

## Human responsibility

AI may generate code.  
AI may write tests.  
AI may propose refactors.  
AI may review patterns.

But human maintainers remain responsible for:

- final merge decisions;
- security and privacy risks;
- license compatibility;
- production readiness;
- alignment with PoCP principles.

## Agent and Skill reputation

Agents and Skills may accumulate reputation when their outputs are used in verified contributions.

However:

- non-human entities do not hold final human governance authority in v0.1;
- their reputation is used to evaluate reliability, not to replace human responsibility;
- the human operator or maintainer remains accountable for submitted code.
